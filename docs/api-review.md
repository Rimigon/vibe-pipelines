# Мнение про Agent API Вайб-Маркетолог

> Ответ на вопрос №2 из вакансии: *«Ваше мнение про наше API для разработчиков
> и вайб-маркетологов, с которым вам предстоит работать
> lk.vibemarketolog.ru/docs/agent-api и MCP для Claude и ChatGPT».*

## Что хорошо (и это немало)

1. **Единый формат ошибки.** `{status:"error", error:"<code>", message,
   details, request_id}` — один раз разобрал, потом ветвишься по стабильному
   машинному коду. `request_id` для поддержки. Это зрелый дизайн, редко
   встречается у российских AI-агрегаторов.

2. **Идемпотентность на `/generate`.** `idempotency_key` с семантикой «тот же
   ключ + то же тело → `replayed:true` без списания, другой тело → 409
   `idempotency_key_conflict`» — это правильно и позволяет строить
   crash-safe агентов. Я на этом построил resume в `vibe-pipelines`.

3. **Защита от лишних списаний как первый класс.** `/generate/estimate`
   (dry-run, бесплатно), `strict=true` (отбрасывать несовместимые поля до
   списания), pre-charge HEAD-валидация URL, автовозврат при сбое (`refunded`),
   дневные лимиты, IP-whitelist, scope fail-closed. Видно, что платформу
   жгли ложные списания и её научили — это опыт, а не теория.

4. **MCP-сервер из коробки.** OAuth 2.1 (RFC 7591, PKCE, refresh rotation) для
   claude.ai/ChatGPT + открытый `oc_`-канал для самописных агентов. Это
   превращает API из «ещё одного эндпоинта» в «тулзу, которую агент может
   вызвать прямо из чата» — сильный ход для продукта про автономных агентов.

5. **Inbox/Bitrix24 с CRM-actions и авто-ответчиком.** Синхронный ответ за 22с,
   добор опоздавшего ответа, ретраи канала не плодят дубли (идемпотентность по
   `dialog_id`), vision/PDF/голосовые вложения, `crm.deal.add`-действия с
   whitelist. Это не демо — это боевой агентный цикл.

6. **Честность в документации.** Прямо написано про footgun с `image_input`,
   про то, что EN-метка пола голоса расходится с русской (`gender_ru`,
   замеры F0), про протухание `result_url` vs подписанный `display_url`. Дока,
   которая предупреждает о реальных граблях, а не хвастается — большая редкость.

## Что бы я улучшил (по делу, не придирки)

### A. Нет уровня сценария — только шаг

Главная дыра. Мультимодельный сценарий (постер→видео→озвучка→музыка) сегодня
собирается на клиенте. См. `proposal-pipeline-endpoint.md` — предлагаю
`POST /generate/pipeline` с server-side DAG. Это закрыло бы вакансийный пункт
«устойчивые генеративные пайплайны» на уровне платформы, а не каждого агента.

### B. Протухание промежуточных URL в многошаговых сценариях

`display_url` живёт 7 дней, `result_url` провайдера протухает быстрее. В
одношаговом сценарии это незаметно; в DAG с шагом «видео 30 мин» зависимый шаг
может не успеть. На бэкенде промежуточные файлы уже есть (галерея ЛК хранит
бессрочно) — логично отдавать их в pipeline по внутреннему пути без TTL.

### C. Footgun имён полей — следствие отсутствия схемы-входа

То, что `image_input`/`image_urls`/`first_frame_url`/`image_url`/
`character_image_url` — пять разных имён для «исходная картинка», и ошибка
молча списывает деньги — это сигнал, что модель-специфичные имена полей не
должны быть интерфейсом для агентов. `/capabilities` уже даёт схему; логично
принимать на `/generate` и **логические** имена (`source_image`,
`source_audio`), маппя их на физические внутри. Я реализовал этот маппинг в
`vibe/capabilities.py` — его можно перенести на бэкенд.

### D. Long voiceover не поддерживает `callback_url`

В доке: «`callback_url` для длинной озвучки пока не поддерживается —
используйте поллинг». Для一致性 и для агентов, которые иначе зависят от
вебхуков, стоит добавить.

### E. `key_cooling_down` — мина для наивных клиентов

Если клиент ретраит 429/503 без `retry_after`, ключ уходит на паузу 5–30 мин.
Дока описывает правило, но это легко нарушить. Хотелось бы, чтобы платформа
сами ретраи с правильным backoff делала для retryable-ошибок (или хотя бы
клиентский SDK официальный), чтобы убрать этот класс ошибок совсем.

### F. Мелочи

- `display_url: null` пока файл не сохранён локально — для агента это лишнее
  ветвление; удобнее всегда отдавать подписанную ссылку сразу.
- `cost` в ответе `/generate` — фактический, но для per-second моделей
  (motion-control, omnihuman) финальная сумма зависит от длительности, которую
  сервер выясняет сам; стоит явно помечать `cost_estimated: true` в таких случаях.
- В `details` ошибок валидации параллельно есть и `details`, и `errors` —
  хорошо что обратно-совместимо, но в доке стоит зафиксировать, что `details`
  канонический, а `errors` deprecated.

## Итог

API зрелый и сделан людьми, которые решали реальные продакшен-проблемы
(идемпотентность, защита от списаний, scope-модель, SSRF-фильтр, MCP, inbox с
CRM-действиями). Главный пробел — **уровень сценария поверх уровня шага**:
сейчас платформа отдаёт кирпичи, а здание каждый агент строит одинаково и с
одинаковыми граблями. Закрыть его серверным `/generate/pipeline` — это и
продуктовый шаг (доступность для нетехов, выше средний чек), и технический
(footgun на корне, непротухающие промежуточные файлы, атомарный бюджет).
Именно поэтому я выбрал это направление для тестового.
